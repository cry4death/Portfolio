# Максим — портфолио разработчика

Русскоязычное портфолио на **Astro, TypeScript и собственном CSS**. Статические страницы, Markdown/MDX-контент, фильтры проектов, светлая и тёмная темы, адаптивное меню. Шрифты поставляются локально вместе с сайтом.

## Запуск

Нужен Node.js 24.

```sh
npm ci
npm run dev
```

Открыть адрес, который напечатает Astro, обычно http://localhost:4321.

В Windows PowerShell при запрете выполнения `npm.ps1` используйте `npm.cmd` вместо `npm`.

```sh
npm run check    # Проверка TypeScript и Astro
npm run build    # Статические страницы в dist/
npm run preview  # Просмотр собранного сайта
```

## Контент

- `src/data/profile.ts` — имя, описание, контакты и навыки. В `skills` рабочие направления (`core`), четыре группы компетенций (`practice`) и инструменты отдельных проектов (`additional`). Поле `evidence` связывает группу с конкретным техническим решением. Учебные инструменты остаются в отдельном `studySkills`. Контакты со значением `null` не становятся ссылками.
- `src/data/education.ts` — программа БГУ: 49 дисциплин, курсовые работы, практика и тема диплома. `studySkills` в `profile.ts` — языки и инструменты, которые Максим подтвердил отдельно.
- `/education/` — страница образования с поиском по дисциплинам. Исходные фотографии приложения к диплому используются только для переноса сведений; сами документы в публичные файлы сайта не включены.
- `public/images/bsu/sources.json` — авторы, источники и лицензии фотографий университета. На страницах также размещены подписи с атрибуцией; WebP-версии распространяются по CC BY-SA 3.0, как и оригиналы.
- `src/content/projects/*.md` — кейсы Lighthouse.by, MARÉA и Lighthouse Mobile. Статусы позволяют отличить опубликованные работы от текущих.
- `src/content/notes/*.md` — заметки. Поддерживается также расширение `.mdx`.
- `src/content.config.ts` — схемы и проверка данных контента.
- `src/styles/global.css` — дизайн, адаптивность и обе темы.
- `src/data/technologies.ts` — соответствие технологий локальным иконкам; `TechBadge.astro` и `TechIcon.astro` — их оформление.
- `public/icons/` — скачанные иконки, исходные ссылки и лицензии. При открытии сайта внешние сервисы иконок не используются.
- `src/components/ProjectVisual.astro` — превью проектов. Для Lighthouse используются скриншоты опубликованного сайта, для MARÉA — настоящие скриншоты локальной сборки, для приложения — мокапы, предоставленные Максимом.
- `summary` в Markdown проекта — краткая сводка роли, периода, команды, задачи, личного вклада и результата перед подробным описанием. Неизвестные период и состав команды можно не указывать.
- `gallery` в Markdown проекта — изображения подробного кейса. Скриншоты Lighthouse.by и их исходные URL находятся в `public/images/projects/lighthouse/`, мокапы приложения — в `public/images/projects/mobile/`. Подготовленные WebP сохраняют прозрачность исходных мокапов.

Чтобы добавить проект, создать Markdown-файл по образцу существующих. Отдельная страница, карточка и категория фильтра появятся автоматически. Для нового типа иллюстрации расширить `visual` в схеме и компоненте. В `liveUrl` и `sourceUrl` указываются реальные публичные ссылки; приватные репозитории не публикуются.

## Публикация в GitHub Pages

Репозиторий: https://github.com/cry4death/Portfolio. Адрес после публикации: **https://cry4death.github.io/Portfolio/**.

1. Отправить исходники в ветку `main` репозитория.
2. Открыть **Settings → Pages → Build and deployment → Source → GitHub Actions**.
3. В **Actions** открыть **Deploy portfolio to GitHub Pages**. Если первый запуск произошёл до включения Pages и завершился ошибкой, выбрать **Re-run all jobs** или **Run workflow → main**.
4. Дождаться успешных заданий `build` и `deploy`, затем открыть адрес сайта.

После каждого push в `main` сайт пересобирается и публикуется автоматически. Workflow находится в `.github/workflows/pages.yml`: Node.js 24, установка из lock-файла, проверка Astro, сборка и загрузка `dist`.

Workflow задаёт `SITE_URL=https://cry4death.github.io` и `BASE_PATH=/Portfolio` через данные репозитория. Локальная разработка без этих переменных продолжает работать от `/`. Компоненты используют `withBase()` для путей; в Markdown внутренние ссылки следует писать относительно страницы, например `../../education/` из кейса проекта.

Проверить именно Pages-сборку в PowerShell:

```powershell
$env:SITE_URL = 'https://cry4death.github.io'
$env:BASE_PATH = '/Portfolio'
npm.cmd run build
npm.cmd run preview
```

В превью открыть `/Portfolio/`. Чтобы вернуться к сборке для корня домена, удалить эти переменные из текущего терминала: `Remove-Item Env:SITE_URL, Env:BASE_PATH`.

GitHub Pages доступен для публичных репозиториев на GitHub Free. Для приватного репозитория нужен тариф, поддерживающий Pages, либо изменение видимости репозитория владельцем. Исходники Astro публикуются через Actions; папки `dist` и `node_modules` коммитить не нужно.

Документация: [Astro: GitHub Pages](https://docs.astro.build/en/guides/deploy/github/), [GitHub: custom workflows](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## Публикация в Cloudflare Workers

Используется Workers Static Assets. Серверный адаптер Astro и база данных для портфолио не нужны.

1. Выбрать уникальное имя Worker в `wrangler.jsonc`.
2. Скопировать `.env.example` в `.env` и указать реальный адрес сайта в `SITE_URL`.
3. Авторизоваться в своём аккаунте Cloudflare и опубликовать:

```sh
npx wrangler login
npm run deploy
```

Для предварительной проверки конфигурации без публикации:

```sh
npm run build
npx wrangler deploy --dry-run
```

В ограниченной среде агента сборка Astro проходит, но Wrangler dry-run может быть недоступен из-за запрета чтения родительских каталогов Windows. Это не заменяет проверку в обычном терминале перед публикацией.

Если `SITE_URL` не задан, сайт собирается без фиктивных canonical URL и sitemap. При заданном URL sitemap генерируется автоматически, а `robots.txt` получает ссылку на него. После смены домена повторить сборку. Для превью при отправке ссылки используется `public/og.png`; её исходник — `public/og.svg`.

Страница 404 обслуживается через `not_found_handling: "404-page"`. Файл `public/_headers` задаёт базовые заголовки и кэширование файлов сборки.

## GitHub и CI

В `.github/workflows/ci.yml` настроены проверки для pull request и push в дополнительные ветки. Проверки `main` и автоматическую публикацию в GitHub Pages выполняет `pages.yml`.

```sh
git init
git add .
git commit -m "Build personal portfolio"
git branch -M main
git remote add origin <URL вашего репозитория>
git push -u origin main
```

`.env`, локальные кэши, `node_modules`, `dist` и артефакты проверки исключены из Git. Учётные данные Cloudflare в исходниках не хранятся.

Конверсия, число клиентов, стаж и проценты владения технологиями не придуманы. Результат Lighthouse описан через опубликованные возможности; измеримые улучшения можно добавить после получения аналитики.
